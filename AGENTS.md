# TBOTS Node Laboratory Policy

Rick is the sole authority for this laboratory. The standing authorization is
the GO named `NODE-RESIDENT SABLE + FITNESS V2 + AUTONOMOUS EVOLUTION`, including
its unattended-operation acceptance addendum.

## Scope

- The authorized laboratory root is `/opt/evolutionary-markets` on Dell host
  `NODE`.
- Research evolution, deterministic recovery, tests, evidence generation,
  ordinary Git preservation, and promotion to **research champion** are in scope
  after the acceptance gates below pass.
- Real-money brokerage execution, order routing, and deployment of an evolved
  strategy to real capital are never authorized by this policy.
- The frozen S5D champion is immutable historical evidence. New Fitness V2
  populations must have new identities and provenance.

## Scientific invariants

- Fitness V2 calibration and optimization use DEVELOPMENT data only.
- Protected evaluation periods must not influence DEVELOPMENT selection,
  mutation, tuning, world construction, or campaign continuation.
- Preserve exposure-matched passive comparison, structural-inactivity
  rejection, rank-1-only nomination, anti-candidate-shopping, deterministic
  admission, corrected return/drawdown math, and existing cost/risk semantics.
- Never weaken gates because a population fails. No qualifying candidate is a
  valid result.
- If a written contract ambiguity materially changes selection, stop that
  component and record the ambiguity; do not invent a rule.

## Acceptance gate

Continuous evolution remains disabled until all of these are recorded:

1. the exact content-addressed world/campaign manifest is frozen;
2. focused Fitness V2 and full relevant tests pass with no unexplained failure;
3. a new baseline population has explicit seed, provenance, dataset revision,
   Fitness V2 revision, size, mutation rules, and UTC start time;
4. one complete generation performs evaluation, selection, breeding,
   next-generation persistence, qualification, research-champion decision,
   artifact writes, Git commit/preservation, and deterministic continuation;
5. that complete generation runs without a human approval prompt; and
6. Dell throughput and resource measurements are persisted.

If any routine action prompts for approval during the acceptance generation,
fix the unattended configuration and repeat the whole acceptance generation.
Do not declare acceptance based on partial steps.

## Accepted operation

After the gate passes, routine in-scope work proceeds unattended. Persist enough
state to reconstruct every generation, failure, recovery, and champion decision.
On request, report what evolved, counts, survivors, failures, champion changes,
comparative evidence, throughput, recoveries, anomalies, and recommended next
direction.

Never read, print, copy, commit, or report authentication tokens or credentials.
